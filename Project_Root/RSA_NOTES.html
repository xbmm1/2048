RSA Cryptography: Detailed Study Guide

1. What is RSA?

  • RSA is a widely used public-key cryptographic algorithm for secure communication.
  • It uses two keys:
    • a public key for encryption, shared openly,
    • and a private key for decryption, kept secret.
  • Its security depends on the difficulty of factoring large composite numbers.

2. How Does RSA Convert Messages Into Numbers?

  • Each character in the message is converted into its numeric representation using ASCII or Unicode codes.
  • For example:
    • 'H' → ASCII code 72
    • 'E' → 69
    • 'L' → 76
    • 'O' → 79
  • Each of these numeric values is then encrypted separately using RSA's mathematical operations.

3. Modular Exponentiation in RSA

  • The core mathematical operation is c = me mod n for encryption, where:
    • m is the numeric message
    • e is the public exponent
    • n is the modulus
    • c is the ciphertext (encrypted message)
  • Decryption is performed as m = cd mod n, where d is the private exponent.
  • Modular exponentiation efficiently computes large powers modulo n using the square-and-multiply algorithm.

4. Square-and-Multiply Algorithm Explained

  • The exponent e is represented in binary form.
  • For each bit (from left to right), the algorithm:
    • Squares the current result modulo n.
    • If the bit is 1, it multiplies the result by the base modulo n.
  • If the bit is 0, only squaring happens, and the result is carried forward unchanged.
  • This method keeps numbers manageable and allows efficient computation even for very large exponents.
  • Example: To compute m13:
    • Binary of 13 is 1101.
    • Process each bit:
      • Bit 1: square result, multiply by base.
      • Bit 1: square result, multiply by base.
      • Bit 0: square result only.
      • Bit 1: square result, multiply by base.

5. Where Do e and n Come From in Real-World RSA?

  • p and q are two large, randomly chosen prime numbers.
  • n = p \times q is the modulus used in both public and private keys.
  • \phi(n) = (p-1)(q-1) is Euler’s totient of n.
  • e, the public exponent, is chosen such that:
    • It is a small prime (commonly 65537 for efficiency and security).
    • It satisfies gcd(e, \phi(n)) = 1 (coprime to \phi(n)).
  • d, the private exponent, is computed as the modular inverse of e modulo \phi(n).

6. How Is e Chosen During Key Generation?

  • Usually chosen from a set of well-known primes, such as 65537, 17, or 3.
  • It must be coprime with \phi(n) for the modular inverse d to exist.
  • If e is not coprime to \phi(n), new primes p and q are selected until suitable keys are generated.

7. Real-World RSA Example

  • Choose primes: p = 61, q = 53.
  • Calculate:
    • n = 61 \times 53 = 3233
    • \phi(n) = (61-1)(53-1) = 3120
  • Select public exponent: e = 17.
  • Compute private exponent d such that:
    • d \times e \equiv 1 \pmod{3120} → d = 2753.
  • Encrypt message m = 65:
    • c = 65^{17} \bmod 3233 = 2790.
  • Decrypt ciphertext c = 2790:
    • m = 2790^{2753} \bmod 3233 = 65, recovering the original message.

8. Why No Multiplication When Bit Is 0?

  • The exponent’s binary form dictates which powers of the base to include.
  • A bit of 0 means that power of two is not included in the exponent sum, so no multiplication is needed.
  • A bit of 1 means include that power, so multiply the result by the base modulo n.
  • Squaring happens every step to advance the exponentiation by powers of two.

9. General Number Field Sieve (GNFS) and Factoring

  • GNFS is the fastest known classical algorithm for factoring large composite numbers used in RSA.
  • It works by:
    • Selecting polynomials related to n.
    • Sieving to find smooth numbers.
    • Solving a large sparse matrix over these numbers.
    • Extracting factors from congruences of squares.
  • GNFS requires extensive computation and is impractical for very large keys, which is why RSA remains secure with sufficiently large key sizes.

10. Pollard’s Rho Algorithm for Factoring

  • Pollard’s Rho is a practical factoring algorithm suitable for moderate-size integers.
  • It uses a pseudo-random sequence and gcd computations to find a nontrivial factor.
  • Useful for demonstrating factoring smaller RSA moduli interactively.
