Mandelbrot Set Visualization







Detailed Explanation: What This Program Is Doing, The Math Behind It, and Why Fractals Are Infinite

1) What This Renderer Does

This program draws the Mandelbrot set on a 2D canvas. Every pixel on the screen is mapped to a complex number c = a + bi. For each pixel, the code runs an iterative test and determines whether that point appears to stay bounded or escape to infinity. The escape speed controls color.

  • Pan: updates offsets (offsetX, offsetY), shifting the complex-plane window.
  • Zoom: changes zoom while keeping the mouse point fixed in the complex plane.
  • Max Iterations: increases/decreases detail at boundaries.
  • Palette Shift: rotates colors without changing the underlying set membership.
  • Worker Mode: splits work into tiles and computes many tiles in parallel on multiple CPU cores.

2) Pixel-to-Complex Mapping

The canvas is a viewport into the complex plane. With view width Wv and view height Hv: 

Wv = (xmax - xmin) / zoom
Hv = (ymax - ymin) / zoom

cReal = xmin + offsetX + (x / width) * Wv
cImag = ymin + offsetY + (y / height) * Hv

So each pixel coordinate (x, y) becomes one complex point c.

3) Core Mandelbrot Iteration Math

For each pixel's complex number c, we iterate: 

z0 = 0
z(n+1) = z(n)^2 + c

Writing z = zr + zi*i, the update becomes: 

zr_next = zr^2 - zi^2 + cReal
zi_next = 2 * zr * zi + cImag

If zr^2 + zi^2 > 4 (equivalently |z| > 2), the point has escaped. If it does not escape by maxIterations, we treat it as in-set for rendering.

4) Coloring Logic (Escape-Time Coloring)

Points that never escaped by the max iteration cutoff are colored black. Others are colored based on how fast they escaped: 

t = (iter / maxIter + paletteShift) % 1
r = floor(9 * (1 - t) * t^3 * 255)
g = floor(15 * (1 - t)^2 * t^2 * 255)
b = floor(8.5 * (1 - t)^3 * t * 255)

This creates smooth bands around the Mandelbrot boundary where dynamics change rapidly.

5) Why Tile-Based Web Workers Help

Mandelbrot cost is non-uniform: some regions escape quickly, while boundary regions require many more iterations. Tile-based scheduling handles this better than simple row-splitting.

How parallel rendering works here

  1. The canvas is split into tiles (for example 64x64 pixel blocks).
  2. A worker pool is created (usually one worker per logical core).
  3. Idle workers request/receive the next tile from a shared queue.
  4. Workers compute RGBA for their tile and send back a transferable buffer.
  5. Main thread paints tile images as they arrive.
  6. A render generation counter discards stale tiles from older zoom/pan states.

Result: much better CPU utilization and reduced wall-clock render time on multi-core machines.

6) Why Fractals Are Infinite

Infinite detail

The Mandelbrot boundary contains structure at every scale. No matter how far you zoom, new detail appears. There is no "last" feature or smallest geometric unit in the mathematical object.

Self-similarity and quasi-self-similarity

Fractals often show repeating motifs under magnification. In Mandelbrot, miniature shapes and spirals recur with variations. This repeat-across-scales behavior is why zoom videos can continue indefinitely.

Iteration never runs out in theory

Mathematically, set membership is defined by behavior under infinitely many iterations. Computers only approximate this with finite iteration limits and finite precision arithmetic.

Important practical note

Your computer eventually hits precision limits (floating-point rounding) and performance limits. So visual zoom is finite in practice, but the underlying fractal definition is unbounded.

7) Program Limits and Approximation

  • Finite iterations: points near the boundary can be misclassified at low maxIterations.
  • Finite precision: JavaScript numbers are IEEE-754 doubles, so extreme zoom loses exactness.
  • Display discretization: continuous math is sampled on a finite pixel grid.

Even with these limits, the renderer captures the key behavior of complex dynamics and shows why fractals are mathematically deep.
